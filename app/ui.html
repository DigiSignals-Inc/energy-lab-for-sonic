🧠 GPU pods

MODELED an AI training cluster on the same fabric — start a collective from the Live tab's GPU cluster scenarios
Each leaf = one rail; 2 GPU servers per rail (8×H100 each). A training step alternates compute with an all-reduce, so fabric load arrives in bursts, not a steady stream. Every GPU value here is modeled, and the power model runs anti-phase to the bursts (utilization is gated down during the all-reduce window). This lab's virtual fabric has no GPU rails, so the GPU scenarios are unavailable here.

🧩 Fabric features

what this fabric can do — and which signals are live, idle, real-but-zero, or absent on a virtual switch
Every capability is classified from already-measured fabric state. active = live right now · idle = present but not exercised (arm a scenario) · real-but-zero = the CLI/framework exists but a virtual switch produces no data · absent = needs real silicon.
